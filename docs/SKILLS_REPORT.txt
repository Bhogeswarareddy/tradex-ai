SECTION E: HONEST DISCLOSURE OF KNOWN ISSUES, BOUNDARIES & RESOLUTIONS
--------------------------------------------------------------------------------
1. BROWSER 'NOT SECURE' WARNING ON PUBLIC IP:
   - Observation: Chrome displays 'Not Secure' when visiting https://43.204.214.188/.
   - Cause: The TLS certificate is self-signed for the bare IP address. The connection
     is fully encrypted via TLS 1.3, but public CAs like Let's Encrypt only issue
     trusted certificates to fully qualified domain names (FQDNs), not raw IP addresses.
   - Resolution: Pointing a free DuckDNS subdomain to the EC2 IP and issuing a Certbot
     certificate turns the Chrome lock icon green.

2. SWAGGER UI (/docs) BLANK SCREEN ON LOCALHOST (RESOLVED):
   - Observation: Visiting https://localhost/docs previously rendered a blank white page.
   - Cause: Nginx's Content-Security-Policy header restricted script-src to 'self',
     blocking Swagger UI's external JavaScript loaded from cdn.jsdelivr.net.
   - Resolution: Added 'cdn.jsdelivr.net' to script-src and style-src in nginx/nginx.conf.
     Swagger UI now renders properly. Direct access via http://localhost:8000/docs works.

3. AUTHENTICATION RATE LIMITER IN RAPID ACCEPTANCE TESTS:
   - Observation: Running catalogue acceptance tests in rapid succession returned HTTP 429
     'RATE_LIMIT_EXCEEDED' on test cases 4 through 12.
   - Cause: Our security rate limiter throttles authentication to 5 attempts per minute to
     prevent brute force credential attacks. Rapid automated tests tripped the threshold.
   - Resolution: Added a short 0.5s sleep delay or auth token caching fixture across test
     runs. This confirms rate limiting is actively defending production.

4. UVICORN STARTUP FAILURE ON HOST VS CONTAINER:
   - Observation: Running 'uvicorn app.main:app' directly in VS Code terminal failed with:
     'could not translate host name db to address'.
   - Cause: Hostname 'db' is an internal Docker DNS name. On the host, the connection
     must point to 'localhost:5432'. Running via Docker Compose resolves 'db' automatically.

5. WINDOWS CRLF LINE ENDINGS ON SHELL SCRIPTS:
   - Observation: Running 'bash -n scripts/backup.sh' in WSL yielded unexpected EOF.
   - Cause: Git checkout on Windows converted line endings to CRLF (\r\n).
   - Resolution: Run 'tr -d \r < script.sh > script_unix.sh' or configure .gitattributes.
